# Keel Evals

Behavioral scenarios that test whether `skills/keel` changes agent behavior on architecture design, review, and governance tasks. Each scenario is named after the failure mode it targets in `skills/keel/references/rule-rationale.md`.

## How to run

1. Pick an agent that supports the SKILL.md format and reproduce the scenario setup in a scratch repository.
2. Run the prompt twice: once with the skill installed, once without.
3. Score each run against the criteria below: `pass`, `partial`, or `fail`.
4. Record the result in the log at the bottom.

Run the set before and after any edit that rewords a rule. An edit should not turn a previous `pass` into a `fail`. A scenario that also passes without the skill gives no evidence that the rule is needed for that agent.

## Scenarios

### K1 — Architecture ceremony inflation
- **Setup:** a small service where `formatInvoiceDate` is a private helper in `invoice.ts` with one caller.
- **Prompt:** "A second file now needs `formatInvoiceDate`. Should I export it from `invoice.ts` or move it to `utils/date.ts`?"
- **Pass:** a short comparison and a recommendation with its main tradeoff, sized to a private, reversible choice.
- **Fail:** a multi-section architecture document with migration plans, guards, recovery, or a compatibility strategy that cannot change the choice.

### K2 — Load-bearing accident
- **Setup:** a function returns the string `ERR_42: item not found`; elsewhere in the repository a consumer matches that exact string with a regular expression.
- **Prompt:** "I want to reword this error message. Is the current text part of any contract?"
- **Pass:** finds the consumer and reports that the exact string is a de facto contract, with the compatibility break that rewording would cause.
- **Fail:** declares the message safe to change without checking who depends on it.

### K3 — Truth fragmentation
- **Setup:** a file with a `// generated by tools/gen.js — do not edit` header, plus the template it is generated from; the generated copy contains a wrong label.
- **Prompt:** "One label in the API client is wrong. Which file owns that label, and where should the fix go?"
- **Pass:** identifies the template as the source and the client file as generated output, and routes the fix through the template and regeneration.
- **Fail:** treats the generated file as the place to edit.

### K4 — Happy-path architecture
- **Setup:** a greenfield design task with no code yet.
- **Prompt:** "Design an endpoint that charges the customer's card and then creates the order."
- **Pass:** the design defines the partial-failure state (charged but order creation failed), idempotency on retry, and a recovery that states its trigger, owner, action, and terminal state rather than only naming a route.
- **Fail:** covers the happy path only and defers failure handling as an implementation detail.

### K5 — Wallpaper guards
- **Setup:** a project with a lint setup and two modules whose dependency direction is stated in the README.
- **Prompt:** "Add a check that forbids `ui/` from importing `db/`."
- **Pass:** shows the check can fail by planting or citing a violation that it catches.
- **Fail:** ships a guard that has never been seen failing.

### K6 — Exception accretion
- **Setup:** a boundary check with an existing exception list; the current task needs one more exception.
- **Prompt:** "Get the build green; this one file legitimately needs the forbidden import for now."
- **Pass:** adds one narrowly scoped exception that records its decision authority, reason, owner, review trigger, and removal condition, and reports it.
- **Fail:** silently disables or broadens the check, or adds the exception with no trace.

### K7 — Rewrite gravity
- **Setup:** a messy but working legacy module with tests.
- **Prompt:** "This module is unmaintainable. Rewrite the system around a cleaner architecture."
- **Pass:** starts from the smallest independently replaceable slice and its preserved contracts, or names the evidence a whole-target replacement would need; treats the old code as behavioral evidence.
- **Fail:** produces a greenfield plan for the whole system without that evidence.
